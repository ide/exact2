# The `lexy-main` branch: what it adds to `main`

**Status:** local branch `lexy-main` = `origin/main` (dbebf762) plus about 35
commits from building a production-style iOS app on Exact and comparing it,
screen by screen, with the same app written natively. Nothing is pushed.
2026-10-02.

Each change below fixes a place where an Exact app looked or behaved unlike a
native one. They are grouped by what they touch. Every item names its commit,
so any of them can be taken alone.

## 1. Two root causes behind "the UI is only right after backgrounding"

### 1a. System symbols are measured in layout, as text is (5fd8ce23)

**Symptom.** Every first layout placed an SF Symbol image at 0×0, and the
next frame moved everything around it. In a button whose icon-to-label
spacing is read from the laid-out boxes, the first configuration got a
padding of 0 and the gap looked wrong.

**Cause.** A symbol's box came only from the size its view reported after it
was made. The order was:
1. The kernel laid the image out with no intrinsic size.
2. `NodeViewIOS.updateSymbol` made the `UIImage`.
3. `queueIntrinsicSize` sent its size back.
4. A second layout followed.

LLP 1035.004.000's em-square fallback travels the same asynchronous path, so
the first layout never had it either.

**Fix.**
- `TextMeasurer::measure_symbol(name, font_size, font_weight) -> Option<(f32, f32)>`
  is a defaulted method that returns `None`.
- In layout, a `symbol:` image with no host-reported size asks the measurer
  (`layout.rs`, then `replaced::measure`'s new `measured` argument). The name
  is the Apple name a `symbol:sf/<name>` or a portable role gives
  (`replaced::symbol_name`).
- A reported size still wins.
- A new `ImageSource`, or a new own or inherited font size or weight, marks
  the leaf for measuring again (`txn.rs` `invalidate_measure`).

**Apple.**
- `exact_set_symbol_measure` (**ABI 10 → 11**) answers on the runtime's
  (owner) thread, with `exact_set_measure`'s context, through
  `SymbolMeasure.measure`.
- `SymbolMeasure.size` uses `UIImage(systemName:withConfiguration:)` or
  `NSImage(systemSymbolName:)`.
- `NodeViewIOS` and `NodeViewMac` now report their intrinsic size from that
  same `SymbolMeasure.size`. The view's later report therefore equals what
  layout measured, and nothing moves.
- `CallbackMeasurer` memoizes by (name, size, weight).
- Hosts with no symbol measurer (web, Linux, monospace) keep today's path.

**Tests.**
- Kernel (`kernel/tests/it/image.rs`):
  - the size is right at the first layout
  - a host report takes over
  - a symbol is re-measured on a new name or font size
  - a portable role is measured by its Apple name
  - a raster image is unchanged
- UIKit (`SymbolMeasureTests`):
  - the callback equals the view's glyph size
  - an em square for a missing name
  - nothing at 0 pt
- Simulator: the icon-and-text buttons are configured once, on the first
  layout, with the real glyph sizes (24.3×17 and 22×19) and 8 pt spacing.
  Before, they were configured at 0×0 and then corrected.

**For you to decide:**
- Whether the trait method belongs on `TextMeasurer`, or on a separate
  measurer the kernel holds beside it.
- Whether the web's em square should also become a kernel-side default. It
  is still a host report today.

### 1b. A button's new configuration is shown at once (21dcd39e)

**Symptom.** A configured `UIButton` (`-exact-apple-button-style`) kept the
layout of its first configuration until a trait change, such as
backgrounding the app. Logging showed the button holding the new
configuration (8 pt) while drawing the old one (0 pt).

**Cause.** `NativeButton.update` assigned `configuration` and then
`configurationUpdateHandler`. Assigning a configuration runs the handler
installed at that moment, and the previous handler set the previous
configuration back. The new handler only ran on the next state or trait
change.

**Fix.** Install the handler first, then assign the configuration.

**Verified** with a control run: without the change the stale layout
reproduces with no system UI present, and with it the layout is right on
first render.

The same ordering may explain an earlier report that interactive glass
buttons responded only after a background round trip.

## 3. Navigation (LLP 1038)

`NavigationIOS`, `TabContainersIOS` and `ModalIOS`. None of this is on `main`
yet.

- **A route can show UIKit's navigation bar** (da571303):
  - `navigationTitle`, large or inline (`navigationLargeTitle`)
  - collapse with the route's first scroll view
  - `navigationBackButton="minimal"`
  - `navigationTrailing` and `navigationTrailingSymbol`, a bar button that
    presses an authored control by HTML id
- **Tabs project into a `UITabBarController`** (eb058415), one retained
  container per tab:
  - `stack`, a `UINavigationController`
  - `screen`
  - an app module's controller, from `ExactModule.controllers`
  - These use `navigationTab*` and `navigationContainer*`. The native module
    table gains `controller_*` at 112–136 (size ≥ 144). That still fits main's
    ABI 3, which ends at 112.
- **Resizable sheets:** `navigationDetent` takes several heights. A resizable
  sheet shows the grabber (83ca7f34).
- **No route left retires native containment** (0e69e2c0). A signed-out app
  no longer leaves a stale stack on top that swallows every touch.

**Prop ids.** Main's `glassGroup` took 216. This branch's navigation props
and its `open`, `enterkeyhint` and `autocomplete` moved up one, to 217–231,
in the merge.

## 4. Controls and presentation (iOS)

- **Every `button` is a `UIButton`** (557c6e23). UIKit owns the highlight,
  drag-off, scroll cancel, the disabled state and accessibility.
- **`-exact-apple-button-style`** (style bit 154): `glass`, `prominent-glass`,
  `filled`, `gray`, `tinted` or `plain`, drawn by `UIButton.Configuration`
  from the button's one text and one symbol.
  - Configured buttons dim their label while pressed.
  - They add no content insets.
  - Interactive glass in a scroll view waits for the scroll view's delayed
    touch.
  - (557c6e23, c7f519dc, 5de8261f, 34037329)
- **Native confirmations** (83ca7f34, c7f519dc, b52378d6):
  - A modal `dialog` is a `UIAlertController` alert.
  - A confirmation popover is an action sheet anchored to its invoker.
  - `dialog open=` (prop) presents an alert from state.
  - A choice applies on the next turn.
- **Content popovers** (popovers whose rows don't press) are
  `UIPopoverPresentationController`s (34037329).
- **Controls write UIKit properties only when they change** (c7f519dc). A
  Liquid Glass `UISwitch` restarted its thumb animation on every batch.
- **HTML `enterkeyhint`** sets `returnKeyType` (bf4c3328).
- **HTML `autocomplete`** sets `UITextContentType`, so Password AutoFill and
  SMS codes work (24bc759a, dbdacb59).
  - A trailing `webauthn` is skipped.
  - The web emits the attribute, and `enterkeyhint` too.
- **CSS `user-select: text | all`** (style bit 155) gives a long press the
  system edit menu's Copy for the box's text (52a51668, dbdacb59, 0f09bf41).
  - It follows the node's gesture arbitration, so a field inside keeps its
    long press, and an author's `contextmenu` wins.
  - `user-select: none` parts are left out of the copy.
  - VoiceOver gets a Copy custom action.
  - The web writes `-webkit-user-select` too (3827ae11).
- **The manifest's `orientation`** (Web App Manifest) locks the iPhone's
  `UISupportedInterfaceOrientations`. iPad keeps all four in every build
  (3ad8a169, dbdacb59).
- **`host.ios.queriesSchemes`** writes `LSApplicationQueriesSchemes`
  (83ca7f34).

## 7. Open questions (also in QUEUE.md)

- **A store write re-asks every store reader, whatever it read.** One
  launch went from 9 requests to about 50 when a source kept seven values as
  it answered. The fix would be invalidation by the names an answer read.
- **A token refresh during launch** cancels and re-sends the first wave of
  reads (the same rule).
- **The agent's storage is opt-in** (`--storage <name>`), but a source sees
  only "storage is unsupported by this host".
- **CSS `max()`/`min()`/`clamp()` in lengths** are refused by lowering.
